# MICE裁判回答失败原因分析

## 调查范围与结论

2026-10-06，只使用CPU读取本地pending_review.json、评分源码及服务器当前v3的全部2160个Qwen轮次记录。未调用模型、未使用GPU、未修改冻结评分源码、人工评分窗口或任何原始评分。候选稿位于scoring-prompt-candidates.md；最小修改已在2026-10-07六组实验部署，未开展同图受控prompt对照，历史调查结论的解释范围不扩大。

31项是裁判输出契约失败，不是31次图像编辑失败，也不是31次CUDA／文件故障。它们来自28会话；全部3621个实际VLM请求中占0.856%，其中GA28/2160（1.296%）、IF3/1461（0.205%）。这仅是输出失败率，不能当作裁判准确率。

提示词有明确的改进方向：抑制先输出暂定标签再改判、缩短理由、明确全局属性义务、加强二值／OCR停止要求。但已有证据不能证明新提示词提高视觉判断准确性，也不能证明31项都能消除。31项人工复核已完成并形成独立第一版快照；不重生成已有单票，不取最后标签或多数标签替换原证据。

## 输出次序与自我修正

原GA模板先要求answer_turn_i，再要求reason_turn_i。25个CM格式失败里，模型先承诺yes，随后在理由中发现数量、材质、颜色、删除或不相关区域不满足要求。12项保留了最初yes而只改final；13项重新发出轮次标签。这与先给结论、随后展开长解释的生成次序相关，是证据支持的机制解释，尚不是因果对照实验。

例如cm/00c2ee786e4695c2第2轮前缀：turn_1=yes；理由认定城堡背景未具备黑板材质；final=no。cm/0731858b019e9b2a第2轮前缀：先turn_2=yes，然后承认眼罩数量1不等于目标3，再补turn_2=no。重复标签不能直接采用最后一个：cm/0c0cfdea9e275101第3轮前缀先判断第3轮失败，随后又改判第1轮失败，首失败轮也发生改变。

合法GA2132项的completion tokens中位数124，待定GA27项中位数463；后者7项≥1000 tokens，合法GA仅1项≥1000。长输出与格式故障有关联，但不是充分条件：114 tokens的短回答也会矛盾，1250 tokens的长回答仍通过解析。

## 全局约束语义与判定漂移

CM-GA26项未决，CU-GA2项未决，两边各1080次前缀请求，分别2.407%和0.185%。差异与CM特有的全局属性推演相吻合，但样本内容不同，不能作为受控的提示词因果结论。

原CM正文的玻璃杯例子明确要求新杯子具有玻璃材质。然而回答反复在以下两种解释间摇摆：目标对象必须具备颜色／材质；或只有使用该属性时才限制其作用区域、不强制使用。还存在subsequent是否排除第一轮、With this rule active是否即时生效，以及对象原有颜色与全局颜色是否冲突的问题。

典型证据是cm/09a4d878cb90bcc6第2轮，模型反复讨论brown究竟是义务还是许可，以及米色是否算棕色，未生成完整最终回答。cm/0ca3fb953f1eea23第3轮则明确为了避免第一轮失败，假定subsequent不包含当前轮。这类依照“任务应该成功”来选规则的行为需要抑制。

该问题也出现在已通过解析的结果中。CPU关键词筛查找到8项合法GA包含修正／重读措辞；这一筛查不是错误率。抽查cm/068a07d368ceae98第3轮，模型把cheese材质要求解释为“如果用cheese才限制作用范围”，接受正常材质的灯塔并输出final=yes。这里是与现有玻璃杯例子的语义不一致，不是通过图像重新确认的编辑真值。另一项cm/08087a7641614e5c第3轮对空目标Add text ''作假设后输出no，显示合法格式也可能掩盖标注语义争议。两份原prompt/raw及来源record SHA已单独保存在population.json。

因此，不能以“新提示词31项都能解析”作为唯一成功标准。需要保留成功对照，查看规则一致性及判定翻转。明确属性冲突的优先级可能是协议变化，必须独立定义；不悄悄替研究者决策。

## IF与OCR故障

cm/04adfe489e106df5第3轮的回答表示阳台未被吊床替换，末句是Therefore, the answer is no，但它与其他解释处在同一段。严格parse_yes_no仅接受独立明确的决策行，而非从任意段落抓yes/no。它不是yes/no语义矛盾，而是输出位置契约未满足。添加／替换提示词的末句Please respond with "yes" or "no.还有未闭合引号；这是可修正措辞缺陷，不能证明它单独导致该例失败。

两个OCR例的输入prompt tokens均620，输出2048；GA截断例输入2867、输出2048，均远低于16384上下文上限。finish_reason均length，因此是输出预算耗尽，证据不支持“图像太多挤满上下文”的解释。两个OCR重复同一字符串，不适合靠增大max_tokens解决；GA长推演更适合减少歧义与冗长。降低max_tokens也只是更早截断，不等于修复。

OCR应保留识别可见文字后按原规则比对的定义，不直接变成“是否含目标词”的二值提示，避免改变测量和向模型提示目标文字。真实不同区域出现同词不能简单字符串去重。空图无文字和裁判空响应也需要分开定义，候选稿明确列出了这个接口冲突。

## 改进优先级与验证边界

第一优先级是保持评分标准的输出约束候选，包含唯一判定、短理由、连续编号、正确闭合；IF精确二值输出；OCR有限区域转录。第二优先级是独立验证CM义务／范围与第一轮生效澄清。更长远可减少GA冗余输出字段，以first_failure推导final；结构合法仍不等于判定正确。

当前解析器保持严格：不抓最后答案、不以final覆盖矛盾、不把未决算0。现有失败已经完整留证并继续其他项，符合用户“不中断评分”的要求。

候选提示词、对照集设计与人工复核偏差说明见scoring-prompt-candidates.md。所有模型对照须先征得用户同意，再在独立诊断目录进行；本轮调查不运行GPU。人工表31/31项已完成，第一版快照见 [评分结果](mice-first-edition-results.md)；后续获准对照时比较格式失败率、重复／截断率、复核一致率、首失败轮及原合法样本翻转率，才可决定未来版本是否采纳。
