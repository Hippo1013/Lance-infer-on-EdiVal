# Lance 编辑伪文字的提示词干扰诊断

## 诊断结论

2026-10-04 的四例第一轮控制实验表明，当时v1适配器额外加入的历史说明和轮次标签，会在这些样本上触发明显的无关文字生成。不能把本次观察简单归为“Lance 原生编辑必然带乱码”。原始编辑指令保持不变，仅移除这些附加文本，四例均不再出现此前的大块无关叠字。

这是提示封装与模型交互的实测问题，不是浏览页面叠字、中文翻译混入模型输入或 PNG 编码乱码。正式 runner 直接保存模型返回的 RGB 图像；页面原样提供 PNG。它也不依赖已经发生的多轮误差累积，因为第一轮即可出现。

## 实验设置

使用已完成的 MICE 全量结果作为原配置参考，定向选择用户正在查看的彩窗、浏览页的消防员和军人，以及既有验收中的花朵样本，共 CM/CU 各两例。这不是随机总体估计。

每例只运行第一轮，固定原图、原始英文指令、base seed 42、按会话派生的图像编码及目标噪声种子。采用原 BF16、30 步、shift 3.5、text CFG 4、image CFG 1、768 面积桶。缓存为 none，关闭 attention 导出。四种模式仅改变附加文本；系统提示与 benchmark 指令均不变。

| 模式 | 历史说明 | CURRENT EDIT 轮次标签 | 明显无关叠字 |
| --- | --- | --- | --- |
| full：现有封装 | 保留 | 保留 | 4/4 |
| label_only：仅轮次标签 | 删除 | 保留 | 1/4 |
| framing_only：仅历史说明 | 保留 | 删除 | 4/4 |
| bare：仅原始指令 | 删除 | 删除 | 0/4 |

16 张生成图均由助手逐张目视检查。判断对象是原图不存在、指令未要求的显著文字覆盖，不把原图的标牌、衣服标识或物体纹理计入；没有运行 OCR 评分或独立人工标注。

四例 full 输出与原全量第一轮输出逐像素完全相同。说明对照复现了用户看到的现象，且本次的缓存/attention 设置差异没有改变这四例的基线。16 份记录的图像哈希、英文指令、目标噪声种子及编码次数已核对；正式全量锁定的 16 个源码文件哈希未改变。

## 机制解释与证据边界

附加文本来自本项目 `src/lance_mice/protocol.py` 的 `HISTORY_EXPLANATION` 和 `history_segments`。这些自然语言说明与标签进入图像生成条件，并不是模型不可见的控制元数据。模型可能把它们部分解释为需要绘制的文字或版式内容；这与文字覆盖的现象一致，但只是机制假设。

本实验同时改变了文本语义、长度及位置，尚未隔离究竟是哪些词、token 位置还是它们与 CFG 的交互起主要作用。不能据四例一个种子断言全部伪文字均有同一来源，也不能推断总体出现率。

此前单轮数值验收已经**明确去掉历史封装**，证明的是该条件下官方 Omni 与适配路径的张量/latent/像素一致；它没有证明附加提示词对生成无副作用。缓存、DP2 和 attention 开关一致性也不能代替提示词消融。此前原生 Lance 速度试跑同样使用这段封装，因此原生输出中的伪文字不能单独证明“不加封装也必然出现”。此前验收在这一点上存在覆盖缺口。

[官方 Lance 报告第 4.4 节](https://arxiv.org/html/2605.18678v1#S4.SS4)说明使用强调文字要求的图像生成提示及 OCR 奖励进行后训练；这提供背景，但不构成“训练导致额外叠字”的因果证据。此次检查官方仓库 issue 标题/正文与报告，没有找到直接解释本次现象的官方结论。
